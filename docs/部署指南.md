# 新 Windows 部署指南

## 1. 准备

- Windows x64，Steam 已登录，CS2 已完整更新；先退出正在运行的 CS2。
- Windows PowerShell 5.1 即可部署。预编译 LocalInspectBridge 已随源码提供，普通部署不需要安装 Visual Studio、.NET SDK 或 PowerShell 7。
- 保留一份完整游戏副本的磁盘空间。本次副本约 71 GiB，脚本检查“源文件总大小 + 5 GiB”；后续游戏更新可能增加。
- 同时运行游戏、服务端和数据库需要额外内存。内存不足时应检查 Windows 分页文件和磁盘空间。
- 初次安装 npm 依赖、下载缺失包和获取未缓存图片需要网络。Steam 及游戏自身也可能需要在线登录和更新。
- `3307/TCP`、`17830/TCP`、`27015/TCP/UDP` 留给本项目；不要同时启动另一份相同端口的检视服。

本次验证版本：CS2 `1.41.9.7`（Client/ServerVersion `2000943`），Metamod `2.0.0-git1490`，CounterStrikeSharp `1.0.380`（带 .NET 10 runtime），WeaponPaints `build-472 / 3.3a`，MenuManager `1.4.1`，PlayerSettings/AnyBaseLib `0.9.4`，MariaDB `11.4.13`，Node `24.22.3`。

固定版本下载链接、文件字节数和 SHA256 均在 [packages.lock.json](../packages.lock.json)。这些是本次实际安装包的指纹；链接在整理时已核对官方来源，部分 GitHub 包还与发布资产的 digest 一致。软件未来更新时，不应单独替换一个 ZIP 后绕过校验。

## 2. 配置路径

复制 `deploy.config.example.psd1` 为 `deploy.local.psd1`。本机配置会被 Git 忽略。

```powershell
@{
    InstallRoot = 'E:\CS2Inspect'
    SourceGamePath = ''
    SteamExe = ''
    SteamId = ''
    TempRoot = 'D:\codex\cs2inspect-cache'
    PackageRoot = ''
}
```

- `InstallRoot`：独立空目录。可以换盘，不能与原游戏、源码仓库、安装包目录重叠。不要填写 Steam 库目录。
- `SourceGamePath`：CS2 安装根目录，即包含 `game\bin\win64\cs2.exe` 的 `Counter-Strike Global Offensive` 文件夹；不是 `game\csgo`。留空时解析 Steam 的 libraryfolders.vdf。
- `SteamExe`：真正的 `steam.exe` 路径，允许空格；留空时从当前用户注册表读取。
- `SteamId`：17 位 SteamID64；留空时使用当前登录 Steam 用户。安装后换账号需要更新部署目录的 `data\profile.json` 并重启检视服务。
- `TempRoot`：必须是存在盘符下的独立目录。npm 缓存和安装进程临时文件放这里，图片缓存固定在安装目录的 `data\preview-images`。
- `PackageRoot`：留空使用仓库的 `packages`，也可以指向旧机器复制来的安装包目录。

操作系统、浏览器和 Steam 本身仍可能写 C 盘；本项目能控制的游戏副本、数据库、运行库和缓存放在所配置的目录。不要手动删除正在使用的系统分页文件。

## 3. 安装

按根目录 README 执行 Get-Packages、Preflight、Install。Windows PowerShell 的 `-ExecutionPolicy Bypass` 只针对这次进程，不改系统永久执行策略。

安装脚本会：

1. 检查路径、端口、空间、原版文件、安装包和自有扩展 DLL 的校验值。
2. 使用 robocopy 复制整份游戏；不使用硬链接、目录链接、`/MOVE` 或 `/MIR`，不写原客户端。
3. 在副本的 `game\csgo` 解压 Metamod、CounterStrikeSharp 和插件；MariaDB/Node 解压到安装目录 `tools`。
4. 安装 `package-lock.json` 锁定的 npm 依赖，生成本机配置和随机密钥。
5. 创建独立 MariaDB 数据目录，临时启动 `127.0.0.1:3307` 创建六张配装表，然后关闭此数据库进程。
6. 修改副本的 gameinfo.gi，加上 Metamod 搜索路径；生成本地检视 cfg 和 WeaponPaints 数据库配置。
7. 比较原版四个关键文件的前后 SHA256，并注册当前用户 `cs2inspect://open` 协议，供 HTML 入口启动本地后台。

安装完成不会立即启动游戏或服务端，不修改分页文件，不创建 Windows 服务，不添加开机自启。只有在用户打开检视时才启动后台进程。

若失败，保留目录与 `logs` 排查。安装器拒绝覆盖非空目录，因此不要对已有目录反复执行 Install。推荐修正原因后改用另一个空目录重装；确认旧目录无须保留的数据、进程已停止后，再自行处理失败副本。独立数据库恢复步骤见迁移维护文档。

## 4. 设置隔离并启动

运行安装目录的 `Enable-Local-Isolation.cmd`，确认 Windows 管理员提示。这一步会启用 Domain/Private/Public 三个防火墙配置文件，并添加两条“仅限独立 cs2.exe”的外部入站阻止规则。原来其他软件依赖防火墙关闭时，其入站行为也可能受影响。

两条规则覆盖 IPv4 非 127/8 地址和 IPv6 非 ::1 地址。数据库、网页仅监听 IPv4 loopback；CS2 的 UDP 实际可能监听通配地址，所以不能只依赖 `-ip 127.0.0.1`。每次启动会验证防火墙和规则完整性，失败则拒绝启动。

双击 `检视控制台.html` → 打开控制台 → 启动检视。若网页启动失败，双击 `打开检视控制台.cmd`。后台地址为 <http://127.0.0.1:17830/>。

加入地图并选好阵营后，用页面选一个皮肤，点“应用到游戏”。首次进入会持 AK，这是地图默认装备；选择其他枪械时会替换对应槽位并切换持有视角。

## 5. 验收

先运行 `deploy\Verify-Deployment.ps1 -InstallRoot <安装目录> -Online`。它检查文件、原版关键文件、防火墙、数据库、网页饰品库、地图和扩展集成，不发送装备修改命令。

随后在游戏中人工检查：

- AK 射击消耗弹匣，R 可以换弹。
- 网页选 AWP，应用后拿到 AWP，皮肤正确。
- 持刀时换另一把刀，应用后仍为持刀且刀具正确。
- 应用手套后保留当前持有视角。
- 打开“探员”，分别选择 T、CT，检查缩略图和大图。在本地地图中应用一名探员，确认角色模型和当前持有武器。
- 单击应用只有一次装备更新，没有两次整套武器刷新。
- 三个分类可见缩略图和大图；断网后已缓存的图片仍可显示。
- 新建组合，保存时可选择目标组合；默认组合没有删除按钮，其他组合删除需确认，单件移除无需确认。
- 在组合中保存步枪、手枪、刀具、手套和探员，点“应用整组”，确认模型与饰品生效，主副武器同时保留。
- 重新启动服务并进入地图，确认热身已取消或等待时间符合预期。
- 地图选择框显示十张地图的中文名与图标；切到荒漠迷城后状态栏正确，刷新网页恢复默认选择炙热沙城 II，实际地图不会自动变化。点击“切换地图”可返回。
- 停止检视服务后本地连接断开，网页仍可再次启动服务。

要验证外部隔离，应从另一台物理设备测试无法访问；同机网卡地址查询不足以证明防火墙阻断。当前项目未声称已做过另一台设备的网络测试。
