# 迁移、升级与故障处理

## 换电脑

推荐复制整个仓库目录（含被 Git 忽略的 `packages`），在新机器安装 Steam/CS2，再按 README 部署。只复制 `.git` 或使用 Git clone 时，安装包不会随行，需要重新下载。

不要把旧 `deploy.local.psd1` 当通用配置直接使用：新机器的盘符、Steam 路径和 SteamID 可能不同。新部署会产生独立的密码、令牌和数据库。

个人组合可以在两边网页后台均停止后单独复制 `data\outfit-groups.json`，放到新安装的同名位置，再打开网页。覆盖目标文件前先备份目标已有组合；此操作是替换，不会合并。图片缓存 `data\preview-images` 也可选复制。它们都不必进入 Git。

若旧机器只有 `data\presets.json`，在新机器首次启动网页前将它放到新安装的 `data` 目录，新版会自动迁入默认组合。若新机器已生成 `outfit-groups.json`，应先备份并移走该文件后再进行迁移，避免覆盖已有数据；同时存在两者时，以组合文件为准。

若要完整迁移数据库：先用旧 MariaDB 自带工具导出 `cs2inspect`，再在新库导入；妥善保管导出文件，不要提交 Git。密码使用交互输入或临时受保护配置，不要放在命令行和聊天记录。旧配装按 SteamID 关联，换 Steam 账号不会自动继承数据库记录；预设方案更便于跨账号搬家。

## 更新 CS2 或插件

新部署会自动安装更新入口。给已有部署补装时，从仓库的 `runtime` 目录复制以下两个文件，保留相对路径。

| 仓库文件 | 已部署目录中的位置 |
| --- | --- |
| `runtime\更新检视服.cmd` | `更新检视服.cmd` |
| `runtime\scripts\Update-Game.ps1` | `scripts\Update-Game.ps1` |

插件依赖引擎内部结构。`packages.lock.json` 固定的是 2026-11-15 已测组合，不是未来永远可用的最新版。

1. 等 Steam 完成 CS2 更新，退出 CS2，并在网页停止检视服务。
2. 双击安装目录的「更新检视服.cmd」。脚本检查 Steam 的安装状态，从原版向独立服务端复制变更文件并校验。新版本改动 gameinfo.gi 时，脚本会合入 Metamod 加载项。如遇自定义配置冲突，会在写入前提示。
3. 看见「更新完成」或「无需复制」后，照常启动检视。脚本把将要替换的文件临时备份到 `TempRoot\cs2-inspect-game-updates`，更新校验通过或自动回滚成功后清理本次批次。如果回滚未完成，按报错中的路径找回旧文件。只检查差异可在安装目录运行 `.\更新检视服.cmd -CheckOnly`。
4. 游戏版本一致但插件仍然报错时，再核对 Metamod、CounterStrikeSharp 和 WeaponPaints 对新版游戏的支持。升级插件前备份个人搭配和数据库，更改依赖时一并更新下载地址、SHA256 和版本记录。
5. LocalInspectBridge 调用 WeaponPaints 的内部方法。升级 WeaponPaints 后检查 `inspect_ready`，再测试换枪、换刀和手套。

不要把服务端的 `addons`、gameinfo.gi 或配置拷回原版 Steam 客户端。不要用硬链接节省原版与副本之间的空间。

## 构建 LocalInspectBridge

普通部署使用 `extensions\LocalInspectBridge\prebuilt\LocalInspectBridge.dll`。DLL 对应此目录源码，校验值在 build-info.json。它只省去本机安装编译器，不包含第三方运行库。

修改源码后，可使用运行于 .NET 10 的 PowerShell 7（本次是 7.6.9）编译，引用已安装 CSS API：

```powershell
pwsh -NoProfile -File .\extensions\LocalInspectBridge\Build.ps1 `
  -ServerRoot E:\CS2Inspect\server `
  -OutputPath D:\codex\LocalInspectBridge-new.dll
```

也提供 `LocalInspectBridge.csproj`，可用 .NET 10 SDK 编译：

```powershell
$env:DOTNET_CLI_HOME='D:\codex\dotnet'
$env:NUGET_PACKAGES='D:\codex\nuget'
dotnet build .\extensions\LocalInspectBridge\LocalInspectBridge.csproj -c Release
```

SDK 构建路径尚未在本机实测；本次实际验证使用上面的 PowerShell/Roslyn 路径。正式替换前停止服务，替换自有插件 DLL，并更新 build-info.json 的 sourceSha256、sha256 和构建记录；只复制自己的 LocalInspectBridge.dll，不覆盖 CSS 的 API DLL。

## 常见故障

| 现象 | 处理 |
| --- | --- |
| SHA256 不匹配 | 核对文件来源、下载是否完整、版本是否被替换。保留报错文件，不跳过校验。 |
| InstallRoot 非空 | 安装器拒绝覆盖现有环境；换一个空目录，或先人工备份/处理旧副本。 |
| npm ci 失败 | 检查 registry.npmjs.org 网络；不要删除 package-lock.json 后随意装新版本。 |
| 数据库初始化失败 | 查看 logs/database-init.log、database-setup.log、mariadb-error.log，确认 3307 未被占用。不要只删 secrets.json，否则会失去现有库密码。 |
| 初始化阶段中断，需要续建数据库 | 确认该副本数据库进程已停止，保留 data/secrets.json，运行安装目录 Node 执行 web/setup-database.mjs；该脚本会复用本机凭据。完成后运行 scripts/Configure-Server.ps1。不要对其他库执行。 |
| 启动时 DLL 缺失 | 先查看缺失的 DLL 名称。若为 Microsoft VC++ runtime，从微软官方安装 x64 运行库；本次 Steam 环境已有，不额外打包。 |
| 地图版本不匹配/插件报错 | 对照游戏版本与插件发布说明，同步更新独立服务端和插件。 |
| 网页可开但无法应用 | 先启动服务、进入本地地图、选阵营；用只读 Verify-Deployment -Online 检查 inspect_ready。 |
| 图片缺失 | 点击重试，检查 raw.githubusercontent.com 连通性；图片失败不阻止游戏内应用。 |
| HTML 入口没响应 | 先用 CMD 入口，再重跑 scripts/Register-PanelProtocol.ps1 修复当前用户协议。 |

## 分页文件与 C 盘

原机曾将分页文件改为 D 盘、下次重启生效。这是该机器单独确认的系统配置，默认安装流程不会迁移这个设置。

保留的 `runtime\scripts\Move-Pagefile-To-D.ps1` 只适合明确拥有 D 盘的机器，要求管理员权限、NTFS 和至少 20 GiB 可用空间。它记录旧设置，把分页文件改到 `D:\pagefile.sys`，重启后生效；不要默认执行，更不要手动删当前页文件。需要恢复时参考它写入 `backups\pagefile-before-move.json` 的原设置。

## 卸载

停止检视服务和网页，退出检视客户端。确认没有该副本的进程后，可自行移除独立安装目录及缓存。若不再使用，可移除当前用户 `HKCU\Software\Classes\cs2inspect` 协议和 `CS2Inspect-Block-External-v4/v6` 两条防火墙规则。不要为此关闭整个 Windows 防火墙。原版 Steam/CS2 不属于卸载目标。
